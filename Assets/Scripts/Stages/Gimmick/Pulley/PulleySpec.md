## A. 目的と方針

| # | 内容 |
|---|---|
| A1 | 重さのパズルとして使う。用途は高所への移動、物の移動など複数 |
| A2 | 部品を自由に組み合わせれば成立する汎用性を最重視する |
| A3 | 物理挙動ではなく計算で動かす。時間は TimeManager の OnTick を使う |
| A4 | 滑車の性質は現実通りに、動き方は遊びやすさ優先で決める |
| A5 | 動きは必ず一意に決まる |
| A6 | 性質 → 計画 → 確認の順で、小さく区切って進める |

## B. 滑車の性質

| # | 内容 |
|---|---|
| B1 | 紐の全長は一定。伸び縮みもたるみもしない |
| B2 | 紐の長さは、シーン上の初期配置の経路長から決める。数値では入力しない |
| B3 | 定滑車は力の向きだけを変える。動滑車は力が半分、移動距離は 2 倍 |
| B4 | 重さは「紐から見た重さ」で比べる。端はそのまま、動滑車は半分 |
| B5 | まだ下がれる部品のうち最も重いものが下がり、まだ上がれる部品のうち最も軽いものが上がる。他は止まったまま。下がる側が重くなければ止まる |
| B6 | 動いている部品が限界に達したら、次の部品に交代する |
| B7 | 紐から見た重さが同じ部品は、同じ距離ずつ動く。1 つが限界に達したら、残りが動き続ける |
| B8 | 釣り合ったら、その場で止まる。「釣り合う位置」は設けない。後から変更しやすい作りにする |
| B9 | 可動域は、紐の長さとストッパーで決まる。端ではぴたりと止まる |
| B10 | ストッパーと障害物は同義。当たり判定を持つオブジェクトにストッパーの目印を付けると、部品がそこで止まる。地面で止めたいときは、地面に目印を付ける |
| B11 | ストッパーに着いた部品は、紐を引く力にならない（B5 の「まだ下がれる」で自然に表現される） |
| B12 | 紐が複数あるとき、ある紐の端を別の紐の部品に結ぶ。その端の重さは「結ばれた先の紐で、次に持ち上がる部品の紐から見た重さ」 |
| B13 | 別の紐の荷物が地面に着くと、紐は緩まないので、元の紐も止まる |
| B14 | 斜めの紐は、動かない部品どうしを結ぶ区間のみ対応。動く部品につながる斜め（V 字吊り）は実装しない |
| B15 | 動く部品は今回は上下のみ。「動く向き」を属性として持たせ、後から横を足せるようにする |

## C. 重さ

| # | 内容 |
|---|---|
| C1 | 整数で持つ。部品ごとに設定できる。既定値は足場 0、滑車 0、おもり 1 |
| C2 | 重さを持つのは Player、実体の AlterPlayer、物。影状態の AlterPlayer は重さなし |
| C3 | 足場側が、幅全体を覆う判定で乗っているものを検知し、重さを合計する |
| C4 | 足場から離れて重さが外れるまでの猶予は秒単位。既定値 0、実運用は 0.1 秒程度。設定できる |
| C5 | 動いている途中で重さが変わったら、速やかに反映する |

## D. 動き方

| # | 内容 |
|---|---|
| D1 | 速さは系（紐の親）に設定する。意味は「紐が送られる速さ」。端はその速さ、動滑車はその半分で動く |
| D2 | 既定はゆっくり |
| D3 | 動き出しも、向きの切替も、交代も、一瞬で切り替える。速さは常に一定（当初は「滑らかに切り替える」としていたが、試したうえで変更。J41） |
| D4 | 揺れ、回転の慣性は扱わない |

## E. 計算の仕組み

| # | 内容 |
|---|---|
| E1 | 計算は Manager の 1 か所で行う。部品は属性と入力を持つだけで、自分では計算しない |
| E2 | 位置の正解は Manager が持つ。部品は結果を受け取って見た目を更新する。足場は Rigidbody の移動も含む |
| E3 | Manager が部品を参照して情報を読む。部品から Manager へ通知する形にはしない |
| E4 | 判定は毎 Tick 行う。前回の結果を持たず、今の入力だけから結果を出す |
| E5 | 判定は Unity に依存しない純粋な計算として切り出す |
| E6 | 1 Tick の中は「全部品を読む → 判定 → 反映」の順を固定し、途中で読み直さない |
| E7 | 判定（目標位置と速さを出す）と移動（目標へ動かす）を分け、移動の層だけ差し替えられるようにする。DOTween へ切り替える余地はここで残す |
| E8 | 判定の結果を画面に出せるようにする |
| E9 | ポーズ中は OnTick の dt が 0 なので、判定も移動も進まない |

| # | 内容 |

## H. 代表的な構成の例

状態：合意済み（2026-10-01）。実装後はこの例で動作を確かめる。

共通の前提：
- Player の重さは 2
- 速さ v は「紐が送られる速さ」（D1）。端は v、動滑車は v/2 で動く
- 「限界」は、紐の長さで決まる端か、ストッパーの位置（B9）
- 初期配置がすでに釣り合っていない場合、ゲーム開始直後から B5 に従って動く。止まった状態から始めたい場合は、釣り合った配置か、限界にある配置で置く

### H1. 定滑車 1 つ（動く部品 2 つ）

構成：足場（0）— 定滑車 — おもり（1）

| 場面 | 期待する動き |
|---|---|
| 誰も乗っていない | おもり 1 ＞ 足場 0。おもりが下がり、足場が上がる。どちらかが限界に達して止まる |
| Player が乗る | 足場 2 ＞ おもり 1。足場が v で下がり、おもりが v で上がる。限界で止まる |
| Player が降りる | おもり 1 ＞ 足場 0。おもりが下がり、足場が上がる |
| おもりを 2 にして Player が乗る | 2 対 2 で釣り合う。その場で止まったまま、何も動かない（B8） |

### H2. 動滑車 1 つ（動く部品 2 つ）

構成：固定端 — 動滑車（荷物 3）— 定滑車 — 足場（0）

紐から見た動滑車の重さは 1.5（B4）。荷物は、動滑車自身の重さの項目で表す（荷物を別の部品にする仕組みは持たない。付け外しが必要になった時点で検討する）。

| 場面 | 期待する動き |
|---|---|
| Player が乗る | 足場 2 ＞ 動滑車 1.5。足場が v で下がり、動滑車が v/2 で上がる |
| Player が降りる | 動滑車 1.5 ＞ 足場 0。動滑車が v/2 で下がり、足場が v で上がる |
| 荷物を 4 にして Player が乗る | 2 対 2 で釣り合う。何も動かない |

### H3. 動く部品 3 つ（交代）

構成：おもり A（1）— 定滑車 — 動滑車（荷物 3、紐から見て 1.5）— 定滑車 — 足場（0）

| 順 | Player が乗ったとき |
|---|---|
| 1 | 最も重い足場（2）が v で下がり、最も軽いおもり A（1）が v で上がる。動滑車は止まったまま |
| 2 | おもり A が上の限界に達する |
| 3 | 次に軽い動滑車（1.5）が v/2 で上がる |
| 4 | 動滑車が上の限界に達するか、足場が下の限界に達して止まる |

| 順 | Player が降りたとき |
|---|---|
| 1 | 最も重い動滑車（1.5）が v/2 で下がり、足場が v で上がる。おもり A は止まったまま |
| 2 | 動滑車が下の限界に達する |
| 3 | 次に重いおもり A（1）が v で下がり、足場が v で上がる |

戻るときは乗ったときの逆再生にはならない。常に「重いものから下がる」ため。

### H4. 同じ重さの部品が 2 つ

構成：おもり A（1）— 定滑車 — 動滑車（荷物 2、紐から見て 1）— 定滑車 — 足場（0）

| 順 | Player が乗ったとき |
|---|---|
| 1 | 足場（2）が v で下がる。おもり A と動滑車は紐から見た重さが同じなので、同じ距離ずつ上がる（B7）。紐の送り量 d に対し、A が d/3、動滑車が d/3 上がる |
| 2 | 先に限界に達した方が止まり、残った方だけが上がり続ける（A なら v、動滑車なら v/2） |

### H5. 紐が 2 本

構成：
- 紐 A：固定端 — 動滑車 P1 — 定滑車 — 足場（0）
- 紐 B：固定端 — 動滑車 P2（荷物 4）— 端 E。E は P1 に結ばれている

紐 A から見た P1 の重さ：E を引き上げるには P2 の紐から見た重さ 2 が必要なので、P1 は 2（B12）。紐 A から見るとその半分の 1。

| 場面 | 期待する動き |
|---|---|
| Player が乗る | 足場 2 ＞ P1 1。足場が v で下がり、P1 と E が v/2 で上がり、P2 が v/4 で上がる |
| Player が降りる | P1 1 ＞ 足場 0。P1 と E が v/2 で下がり、P2 が v/4 で下がり、足場が v で上がる |
| P2 が地面（ストッパー）に着く | 紐 B は緩まないので E はそれ以上下がれず、P1 も足場も止まる（B13）。足場は上の限界に達していなくても止まる |
| その後 Player が乗る | 足場 2 ＞ P1 1。再び足場が下がり、P2 が持ち上がる |

### H6. ストッパー

構成：足場（0）— 定滑車 — おもり（5）。おもりは地面のストッパーに着いている

| 場面 | 期待する動き |
|---|---|
| Player が乗る | 足場 2 ＜ おもり 5。何も動かない。おもりは下がれないので引く力にもならないが、持ち上げるには 5 を超える重さが要る（B11） |

構成：H1 と同じで、足場の途中の高さにストッパーを置く

| 場面 | 期待する動き |
|---|---|
| Player が乗る | 足場が下がり、ストッパーの位置でぴたりと止まる。おもりも同時に止まる（B9、B10） |

## I. スクリプト構成

状態：合意済み（2026-10-01）。置き場所は断りがなければ `Assets/Scripts/Stages/Gimmick/Pulley/`。

| スクリプト | 種類 | 役割 |
|---|---|---|
| `PulleySystem` | MonoBehaviour（系の根） | 経路リスト（部品 ＋ 通る側）、速さ、親の系の登録を持つ。毎 Tick に部品を読み、Solver に渡し、結果で部品を動かす。位置の正解を持つ。親を持たない場合だけ OnTick を購読し、自分の後に子の系を更新する（E1〜E4、F1〜F4） |
| `PulleySolver` | 純粋な C# クラス | 入力（各部品の紐から見た重さ、上下に動ける余地、区間の長さ）から、各部品の動く向きと配分を出す。Unity に依存しない（E5） |
| `PulleyNode` | MonoBehaviour（抽象） | 経路に登録できる部品の共通部分。属性「固定」「重さ」「動く向き」を自分の項目として持つ。同じオブジェクトの重さ供給元（PulleyPlatform など）があれば、その分を重さに加える。系から位置を受け取って見た目を更新する |
| `PulleyWheel` | PulleyNode | 滑車。半径を持つ。固定なら定滑車、固定でなければ動滑車 |
| `PulleyEnd` | PulleyNode | 紐の端。固定なら固定端、固定でなければおもりや足場の端 |
| `PulleyPlatform` | MonoBehaviour | 足場。幅全体を覆う判定で IWeighted を持つものを検知し、猶予つきで重さを合計して PulleyEnd に供給する（C3〜C5）。足場にだけ付ける |
| `PulleyStopper` | MonoBehaviour | 当たり判定を持つオブジェクトに付ける目印。動く部品はこの当たり判定の箱で止まる（F7） |
| `PulleyRope` | MonoBehaviour | 系の経路リストを読んで LineRenderer で描く。編集中は Gizmo でも表示（F8、F9） |
| `IWeighted` | インターフェース。`Assets/Scripts/Interface/` | 「今の重さ」を返す。足場はこれを持つものだけを数える（C2） |
| `WeightHolder` | MonoBehaviour。`Assets/Scripts/Characters/` 配下 | IWeighted の実装。重さを 1 つ持つだけで、Player、AlterPlayer、物に付ける。影状態の AlterPlayer は当たり判定が無効なので足場に検知されず、重さなしになる（J9） |

決めたこと：
- 名前は `PulleyManager` ではなく `PulleySystem`。このプロジェクトでは `XxxManager` が Singleton を意味するため
- 固定／可動はスクリプトで分けず、PulleyNode の「固定」項目で切り替える
- 属性は独立したコンポーネントにせず、PulleyNode の項目として持つ。付け忘れを防ぐため
- 円周ではなく半径を持つ。巻き付き分の長さと回転表示は半径から求める
- 移動の層（E7）は最初は PulleySystem 内に持ち、DOTween へ切り替える判断が出た時点で切り出す

起動時の検査（F4）で警告を出す項目：
- 経路の両端が PulleyEnd になっているか
- 同じ部品が二重に登録されていないか
- 固定の部品に 0 でない重さが設定されていないか
- 親の系の登録と、端を置いた場所が食い違っていないか
